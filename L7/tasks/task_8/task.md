# L7 / Task 8 — Анаграммы

**Анаграммы** — слова из одних и тех же букв в разном порядке: `кот` — `ток` — `окт`, `апельсин` — `спаниель`.
Программа получает текст и находит в нём все группы анаграмм.

## Зачем эта задача

- Главная мысль: **правильно выбранный ключ решает задачу**. Если перебирать все пары слов и сравнивать их буквы, на
  10 000 словах это 50 миллионов пар. А если придумать ключ, одинаковый у всех анаграмм, map сама разложит слова по группам
  за один проход.
- Ключом map может быть только **сравнимый** тип. Слайс рун ключом быть не может (`invalid map key type []rune`), а
  строка — может. Поэтому отсортированные руны склеивают обратно в строку.
- Ещё раз увидеть, что порядок обхода map случайный: чтобы вывод был одинаковым от запуска к запуску, его сортируют.

Где это в жизни: тот же приём «найти ключ, одинаковый у похожих вещей» ищет дубликаты файлов (ключ — хеш содержимого),
объединяет заказы одного покупателя (ключ — e-mail), группирует записи по дате.

## Ввод

Текст до конца ввода: одна или несколько строк. Строки могут быть пустыми, а в начале и в конце строки могут стоять
пробелы. Слова разделены пробелами (одним или несколькими), состоят только из
русских или английских букв, знаков препинания нет. Всего слов от 1 до 10 000, каждое не длиннее 30 букв, в одной строке — не больше 100 слов. Ввод всегда
корректный.

## Что считать анаграммами

- Регистр не важен: сначала переводи каждое слово в нижний регистр через `strings.ToLower`. `Кот` и `ток` — анаграммы.
- Одинаковые слова — не анаграммы друг другу. Если слово (после перевода в нижний регистр) встречается несколько раз,
  в группе оно учитывается **один раз**: `кот КОТ кот ток` — это одна группа `кот ток`.
- Группа печатается, только если в ней хотя бы **два разных** слова.

## Вывод

Каждая группа — на отдельной строке: слова группы в нижнем регистре через один пробел, **отсортированные**. Сами группы
тоже отсортированы — по первому слову **уже отсортированной** группы, то есть по её наименьшему слову (а не по
слову, которое встретилось во вводе первым). Сортируй через `slices.Sort`: он сравнивает строки по кодам символов.

Если ни одной группы нет — одна строка `анаграмм нет`.

## Примеры

Ввод:

```
Кот ток окт кит
сон нос рост сорт торс
КОТ кот
```

Вывод:

```
кот окт ток
нос сон
рост сорт торс
```

`кит` ни с чем не совпал. `КОТ` и `кот` в третьей строке — это уже известное слово `кот`.

---

Ввод:

```
листок слиток столик
апельсин спаниель
кот
ток
```

Вывод:

```
апельсин спаниель
кот ток
листок слиток столик
```

---

Ввод:

```
один два
```

Вывод:

```
анаграмм нет
```

## Как решать

- Напиши функцию `key(word string) string`: переведи слово в слайс рун, отсортируй его через `slices.Sort` и склей обратно
  в строку. У `кот`, `ток` и `окт` ключ одинаковый: `кот` → `[к о т]` → … → `"кот"`, `ток` → `"кот"`.
- Группы храни в `map[string][]string`: ключ → слова с таким ключом.
- Сравнивать слова попарно (двойным циклом по всем словам) нельзя: решение должно делать один проход по словам с map.

## Подсказки

- Отсортировать группы по первому слову можно без особых функций сортировки. Отсортируй каждую группу, собери их первые
  (наименьшие) слова в слайс `[]string` и отсортируй его через `slices.Sort`. Рядом заведи `map[string][]string`: первое слово → вся группа.
  Потом иди по отсортированным первым словам и доставай группы из этой map.
- Чтобы не учитывать слово дважды, запоминай уже встреченные слова: `seen := make(map[string]bool)`. Для нового слова
  `seen[w]` вернёт `false` — нулевое значение `bool`.
- `strings.Join(words, " ")` склеивает слайс слов через пробел.

## Проверь себя

1. Почему ключ — строка, а не сам слайс рун `[]rune`?
   <details><summary>Ответ</summary>

   Ключ map должен сравниваться через `==`, а слайсы через `==` не сравнить: Go не скомпилирует `map[[]rune][]string`.
   Строку сравнить можно, поэтому отсортированные руны склеивают в строку. Подошёл бы и массив, но длина массива — часть
   типа, а слова разной длины.
   </details>

2. `slices.Sort` поставит `ёж` после `яблоко`. Почему?
   <details><summary>Ответ</summary>

   Строки сравниваются по кодам символов Unicode, а не по алфавиту. Буквы `а`–`я` идут подряд (коды 1072–1103), а `ё` стоит
   отдельно, с кодом 1105 — после `я`. Сортировка «по-настоящему по алфавиту» требует отдельных правил для каждого языка.
   </details>

3. Как изменить ключ, чтобы в одну группу попадали слова с одинаковым **набором** букв без учёта повторов (`кот` и `коттт`)?
   <details><summary>Ответ</summary>

   После сортировки убрать подряд идущие одинаковые руны (в пакете `slices` для этого есть `slices.Compact`). Ключ у
   `коттт` станет таким же, как у `кот`. Задача та же, поменялся только ключ, — в этом и сила приёма.
   </details>
