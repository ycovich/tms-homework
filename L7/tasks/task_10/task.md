# L7 / Task 10 — Свой слайс

На лекции мы разобрали, как устроен слайс: массив в памяти, длина `len` и ёмкость `cap`. `append` кладёт элемент в
свободное место, а когда места нет — переезжает в массив побольше. В этой задаче ты **сам напишешь такой слайс**:
тип `IntSlice` с методами `Push`, `Pop`, `Get`, `Set`, `Insert`, `Remove`. Встроенный `append` трогать нельзя: всю его
работу ты сделаешь руками.

Программа — интерпретатор команд: читает команды и выполняет их над одним `IntSlice`. Каждый переезд в новый массив
программа печатает, чтобы было видно, когда и как растёт ёмкость.

## Зачем эта задача

- Понять `append` изнутри: что такое «переезд», почему ёмкость растёт **вдвое**, а не на 1, и почему поэтому добавление в
  конец в среднем быстрое.
- Увидеть цену вставки и удаления **в середине**. Каждый элемент правее нужно сдвинуть на одну позицию. Программа печатает,
  сколько элементов сдвинуто: вставка в начало слайса из миллиона элементов — это миллион сдвигов.
- Потренироваться писать тип с методами: получатель-указатель, ошибки через `error`, полезное нулевое значение
  (`var s IntSlice` — уже готовый пустой слайс, как `var st StringStack` на лекции).

## Тип и правила памяти

```go
type IntSlice struct {
    data   []int // «массив»: место под элементы. Ёмкость = len(data)
    length int   // сколько элементов занято, от 0 до len(data)
}
```

Поле `data` играет роль массива фиксированного размера. Работать с ним можно **только** так:

- создать новый: `make([]int, n)`;
- читать и писать по индексу: `s.data[i]`, `s.data[i] = v`;
- узнать размер: `len(s.data)`.

**Запрещено во всей задаче:** `append`, `copy`, срезы вида `x[a:b]`, пакет `slices`. Всё это делает работу за тебя, а
смысл задачи — сделать её самому. Эти запреты проверяются автоматически.

### Правило роста

Когда нужно положить элемент (`push` или `insert`), а места нет (`length == len(data)`), слайс **переезжает**:

1. новая ёмкость = `1`, если старая была 0, иначе **вдвое больше** старой: 0 → 1 → 2 → 4 → 8 → 16 …;
2. создаётся новый `data` новой ёмкости через `make`;
3. занятые элементы по одному копируются циклом из старого `data` в новый;
4. `s.data` теперь указывает на новый массив. Старый уберёт сборщик мусора.

Ёмкость никогда не уменьшается: после `pop` и `remove` она остаётся прежней.

## Методы

Сигнатуры — ровно такие. Все методы — с получателем-указателем `(s *IntSlice)`.

| Метод                                   | Что делает                                                                                                  |
|-----------------------------------------|-------------------------------------------------------------------------------------------------------------|
| `Len() int`                             | количество элементов (`length`)                                                                             |
| `Cap() int`                             | ёмкость (`len(data)`)                                                                                       |
| `Push(v int)`                           | добавляет `v` в конец, при нехватке места сначала переезжает                                                |
| `Pop() (int, error)`                    | убирает последний элемент и возвращает его. Пустой слайс — ошибка `слайс пуст`                              |
| `Get(i int) (int, error)`               | элемент с индексом `i`. Индекс вне `0 … Len()-1` — ошибка `индекс <i> вне диапазона [0, <Len>)`             |
| `Set(i, v int) error`                   | записывает `v` на место `i`. Ошибка — как у `Get`                                                           |
| `Insert(i, v int) (int, error)`         | вставляет `v` **перед** элементом `i` (при `i == Len()` — в конец). Элементы с `i` и правее сдвигаются вправо. Возвращает, сколько элементов сдвинуто. Допустимо `0 ≤ i ≤ Len()`, иначе ошибка `индекс <i> вне диапазона [0, <Len>]` |
| `Remove(i int) (int, int, error)`       | удаляет элемент `i`, элементы правее сдвигаются влево. Возвращает удалённое значение и сколько элементов сдвинуто. Ошибка — как у `Get` |
| `String() string`                       | элементы в квадратных скобках через пробел: `[1 2 3]`, пустой — `[]`                                       |

Обрати внимание на скобки в текстах ошибок. У `Get`, `Set`, `Remove` правая скобка круглая `)`: `Len()` уже **не**
допустимый индекс. У `Insert` — квадратная `]`: вставить в конец, на место `Len()`, можно.

Сколько сдвинуто:

- `Insert(i, v)`: все элементы, которые были с индексом `i` и правее, то есть `Len() - i` (длина до вставки);
- `Remove(i)`: все элементы правее `i`, то есть `Len() - i - 1` (длина до удаления).

## Команды

Ввод — команды до конца ввода, по одной на строку. Числа — целые. Других команд не бывает, аргументов всегда столько,
сколько указано. В начале слайс пустой: `len 0`, `cap 0`.

| Команда      | Что печатает                                                                                                        |
|--------------|---------------------------------------------------------------------------------------------------------------------|
| `push X`     | если был переезд — строку `grow <старая ёмкость> -> <новая ёмкость>`, иначе **ничего**                              |
| `pop`        | удалённое значение или `ошибка: слайс пуст`                                                                         |
| `get I`      | значение или `ошибка: <текст>`                                                                                      |
| `set I X`    | при успехе **ничего**, при ошибке `ошибка: <текст>`                                                                 |
| `insert I X` | если был переезд — сначала строку `grow …`. Потом `сдвинуто: <K>`. При ошибке — только `ошибка: <текст>`          |
| `remove I`   | `удалено: <значение>, сдвинуто: <K>` или `ошибка: <текст>`                                                          |
| `len`        | длину                                                                                                               |
| `cap`        | ёмкость                                                                                                             |
| `print`      | результат `String()`                                                                                                |

При ошибке `insert` никакого переезда нет: сначала проверяется индекс.

## Пример

Ввод:

```
pop
push 10
push 20
push 30
print
len
cap
insert 0 5
insert 4 40
print
remove 1
get 9
set 0 7
get 0
insert 9 1
print
pop
cap
```

Вывод:

```
ошибка: слайс пуст
grow 0 -> 1
grow 1 -> 2
grow 2 -> 4
[10 20 30]
3
4
сдвинуто: 3
grow 4 -> 8
сдвинуто: 0
[5 10 20 30 40]
удалено: 10, сдвинуто: 3
ошибка: индекс 9 вне диапазона [0, 4)
7
ошибка: индекс 9 вне диапазона [0, 4]
[7 20 30 40]
40
8
```

Разбор: `push 30` при ёмкости 2 переезжает в массив на 4. `insert 0 5` вставляет 5 в начало: места хватает
(3 элемента, ёмкость 4), три элемента сдвигаются. `insert 4 40` вставляет в конец (индекс 4 = длина): места нет —
переезд 4 → 8, сдвигать нечего. `remove 1` удаляет 10 из `[5 10 20 30 40]`, правее него три элемента.

## Как решать

- Тип и методы — ровно как в таблице выше. `main` только разбирает команды, вызывает методы и печатает результат.
- Метод `Push` ничего не печатает и не возвращает. Как `main` узнаёт, что был переезд? Запомни `s.Cap()` до вызова и
  сравни с `s.Cap()` после.
- Методы не печатают ошибки сами, а возвращают `error` — как в task_2 и task_9. Например, `Get` при плохом индексе
  делает `return 0, fmt.Errorf("индекс %d вне диапазона [0, %d)", i, s.length)`, а при хорошем — `return s.data[i], nil`.
  Печатает `main`: `fmt.Println("ошибка:", err)`.
- Переезд вынеси в отдельный метод, например `grow()` (со строчной буквы: он для внутреннего использования). Его вызывают
  и `Push`, и `Insert`.

## Подсказки

- Сдвиг вправо при вставке делай **с конца**: `for j := s.length; j > i; j--` и `s.data[j] = s.data[j-1]`. Если сдвигать
  с начала, каждый следующий элемент затрёт себя предыдущим, и получатся одинаковые значения.
- Сдвиг влево при удалении — наоборот, с начала: `s.data[j] = s.data[j+1]`.
- `Pop` не обязан ничего стирать в `data`: достаточно уменьшить `length`. Значение за границей длины просто будет
  перезаписано следующим `Push`. Ровно так поступает `s = s[:len(s)-1]` у настоящего слайса.
- Строку для `String()` удобно собирать в `strings.Builder` или через `+=` и `strconv.Itoa`.

## Проверь себя

1. Почему ёмкость растёт вдвое, а не на 1?
   <details><summary>Ответ</summary>

   Каждый переезд копирует все элементы. При росте на 1 переезд был бы на **каждом** `push`: для миллиона элементов это
   1 + 2 + … + 1 000 000 ≈ 500 миллиардов копирований. При удвоении переездов всего около 20, а копирований суммарно
   меньше 2 миллионов — в среднем меньше двух копирований на элемент. Настоящий `append` растёт вдвое для небольших
   слайсов и примерно в 1,25 раза для больших, чтобы не тратить слишком много памяти.
   </details>

2. Встроенный `append` возвращает новый слайс (`s = append(s, x)`), а наш `Push` ничего не возвращает. Почему так можно?
   <details><summary>Ответ</summary>

   Наш `Push` получает **указатель** на `IntSlice` и меняет `data` и `length` прямо в оригинале. Встроенный слайс
   передаётся в `append` по значению: функция получает копию заголовка (`ptr`, `len`, `cap`) и может вернуть новый
   заголовок только через результат. Поэтому его нужно присваивать обратно.
   </details>

3. Почему вставка в начало дорогая, а в конец — дешёвая?
   <details><summary>Ответ</summary>

   Элементы лежат в памяти подряд, без «дырок». Чтобы освободить место в начале, нужно сдвинуть **все** элементы. В конце
   место уже свободно (если есть ёмкость), сдвигать нечего. Если вставок в начало очень много, выбирают другую
   структуру, например связный список.
   </details>
