# L7 / Task 19 ★ — Телефонная книга на дереве (необязательная)

Задача со звёздочкой: её можно не делать. Перед ней прочитай про O-нотацию — ссылки в [L7/README.md](../../README.md).

Телефонная книга: имя → номер. Хранить её будем не в map и не в слайсе, а в **двоичном дереве поиска** (BST, binary
search tree). Каждый узел хранит имя, номер и ссылки на двух «детей». **Слева** от узла все имена меньше, **справа** —
больше:

```
            Мария
           /     \
        Вера     Юрий
        /
     Анна
```

Чтобы найти имя, начинаем с корня (верхнего узла): меньше — идём влево, больше — вправо. Каждый шаг отбрасывает целое
поддерево. А обход «левое поддерево → узел → правое поддерево» выдаёт все имена **по порядку** — map так не умеет.

## Зачем эта задача

- Понять, как дерево совмещает быстрый поиск и порядок. У map нет порядка. У отсортированного слайса медленная вставка в
  середину. Дерево даёт и то и другое — пока оно **сбалансировано**.
- Увидеть, что рекурсия естественна для дерева: «найти в дереве» = «сравнить с корнем и найти в левом или правом
  поддереве».
- Своими глазами увидеть худший случай: если добавлять имена по алфавиту, дерево вытягивается в «палку», и поиск
  становится обычным перебором.

## Узел

```go
type Node struct {
    Name, Phone string
    Left, Right *Node // nil — ребёнка нет
}
```

Пустое дерево — `nil`. Имена сравниваются обычными `<` и `>` для строк (по кодам символов).

## Команды

Ввод — команды до конца ввода. Имя и номер — одно слово без пробелов. Ввод всегда корректный.

| Команда            | Что делает и печатает                                                                                              |
|--------------------|--------------------------------------------------------------------------------------------------------------------|
| `add <имя> <номер>` | если имени нет — добавляет новый узел-лист на его место в дереве, печатает `добавлен <имя>`. Если есть — меняет номер, печатает `обновлён <имя>` |
| `find <имя>`       | номер или `нет`                                                                                                    |
| `list`             | все записи **по порядку имён**, по строке на запись: `<имя>: <номер>`. Пустое дерево — ничего                      |
| `height`           | высоту дерева: число узлов на самом длинном пути от корня вниз. Пустое дерево — 0, один узел — 1                   |
| `count`            | число записей                                                                                                      |

Дерево не перестраивается: новый узел всегда становится листом там, куда привёл поиск.

## Примеры

Ввод:

```
add Мария 333
add Вера 111
add Юрий 555
add Анна 000
add Вера 112
find Вера
find Олег
list
height
count
```

Вывод:

```
добавлен Мария
добавлен Вера
добавлен Юрий
добавлен Анна
обновлён Вера
112
нет
Анна: 000
Вера: 112
Мария: 333
Юрий: 555
3
4
```

Это дерево с картинки выше. Самый длинный путь — Мария → Вера → Анна, высота 3.

---

Ввод:

```
add A 1
add B 2
add C 3
add D 4
height
count
```

Вывод:

```
добавлен A
добавлен B
добавлен C
добавлен D
4
4
```

Имена пришли по порядку: каждое следующее больше всех предыдущих и уходит вправо. Дерево стало «палкой»
A → B → C → D, высота равна числу узлов.

## Как решать

- Функции `insert`, `find`, `list`, `height`, `count` — рекурсивные. Каждая получает узел (`*Node`, возможно `nil`), и
  базовый случай у всех — пустое дерево `nil`.
- Map и сортировку в этой задаче не используй: порядок даёт само дерево.

## Подсказки

- `insert` удобно возвращать новый корень поддерева: `func insert(t *Node, name, phone string) (*Node, bool)`. Если `t == nil`,
  верни новый узел. Иначе вставь в нужное поддерево и присвой: `t.Left, added = insert(t.Left, name, phone)`. Второй
  результат — было ли имя новым.
- Высота: пустое дерево — 0, иначе `1 + max(высота левого, высота правого)`. `max` — встроенная функция.

## Проверь себя

1. Сколько шагов нужно, чтобы найти имя в сбалансированном дереве из 1 000 000 записей? А в «палке»?
   <details><summary>Ответ</summary>

   В сбалансированном — около 20: высота такого дерева ≈ log₂ n, O(log n). В «палке» — до 1 000 000, как перебор слайса,
   O(n). Поэтому в настоящих библиотеках деревья **самобалансирующиеся** (красно-чёрные, AVL): при вставке они
   поворачивают узлы, чтобы высота оставалась ≈ log n.
   </details>

2. Когда дерево лучше map?
   <details><summary>Ответ</summary>

   Когда нужен **порядок**: вывести всё по алфавиту, найти всех от «К» до «М», найти ближайшее большее значение. Map
   отвечает на вопрос «есть ли ключ» в среднем быстрее, но про порядок ничего не знает. Если нужен только поиск по точному
   ключу — бери map.
   </details>
