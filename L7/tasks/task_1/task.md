# L7 / Task 1 — Контрольная сумма

Когда данные передают по сети или записывают на диск, к ним часто добавляют **контрольную сумму** — число, посчитанное
из самих данных. Получатель считает сумму заново и сравнивает: не совпало — значит, данные повредились по дороге.

Самая простая контрольная сумма — сложить все байты. Но хранить её хотят в **одном байте**, то есть в типе `uint8`.
Сумма байтов быстро перерастает 255, и тут работает переполнение, знакомое по уроку 5: после 255 идёт 0. Здесь
переполнение — не ошибка, а то, что нужно.

Программа получает строку и печатает про неё шесть чисел.

## Зачем эта задача

- Увидеть, что строка — это байты. Буква «П» — не один символ, а два байта, и оба больше 127.
- Понять, что тип задаёт **размер** числа. Одна и та же сумма в `int` и в `uint8` — разные числа.
- Разобраться в преобразованиях: `int(b)` расширяет байт до `int` без потерь, а `int8(x)` берёт те же 8 бит и читает их
  как число со знаком. Биты те же — смысл другой.

## Ввод

Одна строка — непустой текст длиной до 1000 байт. В нём могут быть вообще любые символы. Ввод всегда считается
корректным.

## Вывод

Шесть строк, ровно в таком виде:

```
байт: <длина строки в байтах>
не-ASCII байт: <сколько байтов строки больше 127>
сумма int: <сумма всех байтов, посчитанная в переменной типа int>
сумма uint8: <сумма всех байтов, посчитанная в переменной типа uint8>
сумма % 256: <сумма из строки «сумма int», взятая по модулю 256>
uint8 как int8: <сумма из строки «сумма uint8», преобразованная в int8>
```

## Примеры

Ввод:

```
Go
```

Вывод:

```
байт: 2
не-ASCII байт: 0
сумма int: 182
сумма uint8: 182
сумма % 256: 182
uint8 как int8: -74
```

Байты строки `Go` — 71 и 111, их сумма 182. В `uint8` число 182 помещается. А в `int8` помещаются только числа от −128
до 127, и те же 8 бит читаются как 182 − 256 = −74.

---

Ввод:

```
Привет, Go!
```

Вывод:

```
байт: 17
не-ASCII байт: 12
сумма int: 2501
сумма uint8: 197
сумма % 256: 197
uint8 как int8: -59
```

Шесть русских букв по 2 байта — это 12 байтов больше 127. Ещё 5 байтов (`,`, пробел, `G`, `o`, `!`) — обычные ASCII.

## Как решать

- Обходи строку **по байтам**: `for i := 0; i < len(s); i++` и `s[i]`. Не через `range`: `range` идёт по рунам, а нам
  нужны именно байты.
- Сумму для строки «сумма uint8» копи в переменной типа `uint8` (`var sum8 uint8`) и прибавляй к ней байты прямо в
  цикле. Считать её через `% 256` нельзя: смысл задачи — увидеть, что переполнение даёт тот же результат.
- Строку «сумма % 256» считай из суммы типа `int`.
- Последнюю строку получи преобразованием `int8(...)` из суммы типа `uint8`.

## Подсказки

- `s[i]` имеет тип `byte`, а `byte` — это другое имя `uint8`. Поэтому `sum8 += s[i]` складывает без преобразований, а
  `sum += s[i]` при `sum int` не скомпилируется: `mismatched types int and byte`. Нужно `sum += int(s[i])`.
- Числа печатаются как обычно: `fmt.Println("байт:", len(s))` ставит пробел после двоеточия сам.

## Проверь себя

1. Почему строки «сумма uint8» и «сумма % 256» всегда совпадают?
   <details><summary>Ответ</summary>

   `uint8` хранит только 8 младших бит числа. Переполнение «выбрасывает» всё, что больше 255, — ровно то же делает
   остаток от деления на 256 = 2⁸. Поэтому переполнение беззнакового типа — это счёт по модулю 2ⁿ.
   </details>

2. Что напечатает этот код?

   ```go
   var u uint8 = 200
   var i int8 = -1
   fmt.Println(int8(u), uint8(i))
   ```
   <details><summary>Ответ</summary>

   `-56 255`. Преобразование между целыми типами одного размера не меняет биты, меняется только то, как их читают. 200 =
   `11001000` в двоичной записи, со знаком это 200 − 256 = −56. А −1 со знаком — это `11111111`, без знака 255.
   </details>

3. Почему у строки `Привет, Go!` «не-ASCII байтов» 12, а не 6?
   <details><summary>Ответ</summary>

   ASCII — это коды от 0 до 127, в один байт помещаются только английские буквы, цифры и знаки. Русская буква в UTF-8
   занимает 2 байта, и **оба** больше 127. По этому признаку программы отличают байты многобайтового символа от
   обычного ASCII.
   </details>
