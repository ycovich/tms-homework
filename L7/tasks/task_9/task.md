# L7 / Task 9 — Банк

Нужно написать маленький банк: открывать счета, класть и снимать деньги, переводить их между счетами. Логика счёта
живёт в **отдельном пакете** `bank`, а `main` только читает команды и вызывает методы.

Главное правило банка: **баланс меняется только через методы**. Никто снаружи пакета не может написать
`acc.balance = 1000000`: компилятор этого не пропустит.

## Зачем эта задача

- Понять, зачем имена со строчной буквы. Поле `balance` видно только внутри пакета `bank`, поэтому все изменения баланса
  проходят через `Deposit`, `Withdraw` и `TransferTo`, а они проверяют правила. Это называется **инкапсуляция**: данные
  спрятаны, наружу торчат только безопасные действия.
- Попрактиковаться в получателе-указателе: методы, которые меняют счёт, обязаны получать `*Account`.
- Увидеть, почему в map хранят **указатели** на структуры: `map[string]*bank.Account`.

Где это в жизни: так устроен почти любой серьёзный код. Тип `strings.Builder` из стандартной библиотеки прячет свой
буфер, а `bufio.Scanner` — своё состояние. Пользоваться ими можно только через методы.

## Пакет `bank`

Напиши в `bank/account.go` ровно такой набор (имена и сигнатуры — как здесь):

```go
package bank

type Account struct {
    owner   string // со строчной буквы: снаружи пакета не видно
    balance int
}

func NewAccount(owner string) *Account            // новый счёт с балансом 0
func (a *Account) Owner() string                  // имя владельца
func (a *Account) Balance() int                   // текущий баланс
func (a *Account) Deposit(amount int) error       // положить
func (a *Account) Withdraw(amount int) error      // снять
func (a *Account) TransferTo(to *Account, amount int) error // перевести на счёт to
```

Правила. Тексты ошибок — **ровно** такие:

| Метод        | Ошибка, если…                                         | Текст ошибки                                     |
|--------------|-------------------------------------------------------|--------------------------------------------------|
| `Deposit`    | `amount <= 0`                                         | `сумма должна быть больше нуля`                  |
| `Withdraw`   | `amount <= 0`                                         | `сумма должна быть больше нуля`                  |
| `Withdraw`   | `amount` больше баланса                               | `недостаточно средств: баланс <B>, нужно <amount>` |
| `TransferTo` | `to` — тот же самый счёт, что и `a`                   | `нельзя перевести на тот же счёт`                |
| `TransferTo` | дальше — те же правила, что у `Withdraw`, для счёта `a` | те же тексты                                   |

Проверки идут сверху вниз, первая сработавшая побеждает. При ошибке баланс не меняется. Снять **весь** баланс можно:
при `amount` равном балансу останется 0.

## Команды

Ввод — команды до конца ввода, по одной на строку. Имена счетов — одно слово без пробелов, суммы — целые числа (могут
быть нулём или отрицательными). Других команд не бывает, у каждой ровно столько слов, сколько указано.

| Команда                       | Что напечатать при успехе           |
|-------------------------------|-------------------------------------|
| `open <имя>`                  | `открыт счёт <имя>`                 |
| `deposit <имя> <сумма>`       | `<имя>: <новый баланс>`             |
| `withdraw <имя> <сумма>`      | `<имя>: <новый баланс>`             |
| `transfer <откуда> <куда> <сумма>` | `<откуда>: <баланс>, <куда>: <баланс>` |
| `balance <имя>`               | `<имя>: <баланс>`                   |

Ошибки печатаются одной строкой `ошибка: <текст>`:

- `open` для уже существующего имени — `ошибка: счёт <имя> уже есть`;
- любая команда с несуществующим счётом — `ошибка: нет счёта <имя>`. У `transfer` сначала проверяется `<откуда>`,
  потом `<куда>`;
- метод вернул ошибку — `ошибка: <текст ошибки метода>`.

## Пример

Ввод:

```
open anna
open boris
open anna
deposit anna 500
withdraw anna 800
withdraw anna 0
transfer anna boris 200
transfer anna anna 10
transfer anna vera 10
balance boris
deposit vera 5
```

Вывод:

```
открыт счёт anna
открыт счёт boris
ошибка: счёт anna уже есть
anna: 500
ошибка: недостаточно средств: баланс 500, нужно 800
ошибка: сумма должна быть больше нуля
anna: 300, boris: 200
ошибка: нельзя перевести на тот же счёт
ошибка: нет счёта vera
boris: 200
ошибка: нет счёта vera
```

## Как решать

- Вся логика денег — в пакете `bank`. `main` не считает балансы и не проверяет суммы: он только вызывает методы и печатает
  результат.
- Поля `owner` и `balance` — со строчной буквы. Методы, которые меняют счёт, — с получателем-указателем `(a *Account)`.
  По правилу с лекции, раз часть методов с указателем — делай указателями все.
- Счета в `main` храни в `map[string]*bank.Account`.

## Подсказки

- Методы, которые могут не сработать, возвращают `error` — как `parsePrice` в task_2 (рецепт — в разделе
  [«Ошибки» в L7/README.md](../../README.md#ошибки-как-вернуть-и-как-проверить)). Ошибку без чисел создавай через
  `errors.New("...")`, с числами — через `fmt.Errorf("недостаточно средств: баланс %d, нужно %d", ...)`. Всё хорошо —
  `return nil`. В `main`: `if err := acc.Deposit(amount); err != nil { fmt.Println("ошибка:", err) }`.
- В `TransferTo` не нужно повторять проверки `Withdraw`: сначала проверь «тот же счёт», потом вызови `a.Withdraw(amount)`.
  Если он вернул ошибку — верни её как есть, иначе прибавь сумму счёту `to`. Внутри пакета `bank` поле `to.balance`
  видно.
- «Тот же самый счёт» — это тот же адрес: `to == a`. Указатели сравниваются через `==`.

## Проверь себя

1. Почему счета хранятся в `map[string]*bank.Account`, а не в `map[string]bank.Account`?
   <details><summary>Ответ</summary>

   `m["anna"]` для map со структурами отдаёт **копию**. Будь `Deposit` с получателем-значением, он изменил бы копию,
   и баланс в map остался бы прежним. А с получателем-указателем `m["anna"].Deposit(…)` вообще не скомпилируется: у
   элемента map нет адреса. Map указателей решает обе проблемы: копируется адрес, а счёт один.
   </details>

2. Можно ли из `main` создать счёт без `NewAccount`, например `bank.Account{}`? И `bank.Account{owner: "anna"}`?
   <details><summary>Ответ</summary>

   `bank.Account{}` — можно: получится счёт с пустым владельцем и балансом 0. `bank.Account{owner: "anna"}` — нельзя:
   поле `owner` не видно снаружи пакета. Поэтому конструктор `NewAccount` — единственный способ задать владельца.
   </details>

3. Зачем методы `Owner()` и `Balance()`, если можно было бы сделать поля `Owner` и `Balance` с заглавной буквы?
   <details><summary>Ответ</summary>

   Поле с заглавной буквы можно не только прочитать, но и **записать** откуда угодно. Метод `Balance()` даёт только
   чтение. Записать можно лишь через методы с проверками. Так правило «баланс не бывает отрицательным» нельзя обойти.
   </details>
