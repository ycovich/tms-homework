# L7 / Task 15 ★ — Стек вызовов своими глазами (необязательная)

Задача со звёздочкой: её можно не делать. Делай её после task_11 — там разобрана ловушка `defer`, которая понадобится и здесь.

На лекции была рекурсия: функция вызывает саму себя для задачи поменьше, а незавершённые вызовы ждут в **стеке
вызовов**. Это трудно представить, пока не увидишь. Здесь программа покажет стек сама: при каждом входе в функцию она
печатает строку «→», при каждом выходе — строку «←» с результатом. Отступ показывает глубину: чем глубже вызов, тем
правее строка.

## Зачем эта задача

- Увидеть, что вызовы завершаются **в обратном порядке**: последний начатый заканчивается первым. Поэтому это и
  называется стеком: как стопка тарелок.
- Увидеть, как ветвится рекурсия у чисел Фибоначчи: `fib(5)` считает `fib(3)` дважды, а `fib(2)` — трижды. Отсюда
  понятно, почему наивная рекурсивная `fib(50)` будет считаться очень долго.
- Применить `defer` по назначению: «сделать при выходе из функции, через какой бы `return` мы ни вышли». И ещё раз
  наступить, а потом не наступать, на грабли «аргументы `defer` вычисляются сразу».

## Функции

- `fact(n)`: `fact(0) = 1`, `fact(n) = n * fact(n-1)`.
- `fib(n)`: `fib(0) = 0`, `fib(1) = 1`, `fib(n) = fib(n-1) + fib(n-2)`. В `fib(n)` сначала вызывается `fib(n-1)`, потом
  `fib(n-2)`, именно в таком порядке.

## Ввод

Две строки: имя функции, `fact` или `fib`, и целое число `n`. Для `fact` −5 ≤ `n` ≤ 20, для `fib` −5 ≤ `n` ≤ 12. Ввод
всегда корректный.

## Вывод

Если `n < 0` — одна строка `ошибка: n должно быть не меньше 0`.

Иначе — трасса вызовов и в конце строка `ответ: <результат>`. Трасса:

- при входе в вызов: `<отступ>→ <имя>(<n>)`;
- при выходе из вызова: `<отступ>← <имя>(<n>) = <результат>`;
- отступ — **два пробела** на каждый уровень глубины. Самый первый вызов — глубина 0, без отступа. Вызовы из него —
  глубина 1, два пробела, и так далее.

`→` и `←` — символы стрелок Unicode (скопируй их из условия). После стрелки — один пробел.

## Примеры

Ввод:

```
fact
3
```

Вывод:

```
→ fact(3)
  → fact(2)
    → fact(1)
      → fact(0)
      ← fact(0) = 1
    ← fact(1) = 1
  ← fact(2) = 2
← fact(3) = 6
ответ: 6
```

---

Ввод:

```
fib
3
```

Вывод:

```
→ fib(3)
  → fib(2)
    → fib(1)
    ← fib(1) = 1
    → fib(0)
    ← fib(0) = 0
  ← fib(2) = 1
  → fib(1)
  ← fib(1) = 1
← fib(3) = 2
ответ: 2
```

---

| Ввод: функция | Ввод: `n` | Вывод                                            |
|---------------|-----------|--------------------------------------------------|
| `fact`        | `0`       | `→ fact(0)` / `← fact(0) = 1` / `ответ: 1`       |
| `fib`         | `-1`      | `ошибка: n должно быть не меньше 0`              |

В таблице `/` разделяет строки вывода.

## Как решать

- `fact` и `fib` — рекурсивные функции с параметром глубины: `fact(n, depth int) (res int)`. Результат — **именованный**.
- Строку входа печатай в начале функции. Строку выхода печатай **через `defer`**, объявленный сразу после строки входа, —
  а не перед каждым `return`. У `fib` два места выхода (база и шаг), и `defer` сработает при обоих.
- Проверку `n < 0` вынеси в отдельную функцию-обёртку, которая возвращает `(int, error)`, как `Factorial` на лекции.
  Сами рекурсивные функции отрицательных `n` не получают.

## Подсказки

- `defer fmt.Printf("← fact(%d) = %d\n", n, res)` напечатает `= 0`: `res` вычислится в момент объявления `defer`, когда
  результат ещё не известен. Отложи анонимную функцию: `defer func() { fmt.Printf(…, res) }()`. Она прочитает `res` при
  выходе. Именованный результат `res` к этому моменту уже равен тому, что вернул `return`.
- Отступ: `strings.Repeat("  ", depth)` — строка из `depth` повторов двух пробелов.

## Проверь себя

1. Сколько вызовов делает `fib(5)`? А `fib(30)`?
   <details><summary>Ответ</summary>

   `fib(5)` — 15 вызовов, `fib(30)` — больше 2,6 миллиона. Число вызовов растёт почти как сами числа Фибоначчи, то есть
   экспоненциально: каждое следующее `n` примерно в 1,6 раза дороже предыдущего. Если запоминать уже посчитанные значения
   (например, в map), каждое `fib(k)` считается один раз, и вызовов становится около `2n`.
   </details>

2. Почему у `fact(20)` самая длинная цепочка вложенных вызовов — 21 вызов, а у `fib(20)` — всего 20?
   <details><summary>Ответ</summary>

   У `fact` цепочка `20 → 19 → … → 0`: 21 вызов. У `fib` самая
   длинная цепочка `20 → 19 → … → 1`: 20 вызовов. В `fib(1)` рекурсия останавливается сразу. В трассе это видно по отступам:
   самый глубокий вызов `fact(0)` — глубина 20, то есть 40 пробелов. Длина цепочки важна, потому что стек вызовов не
   бесконечный: при слишком глубокой рекурсии будет `stack overflow`.
   </details>
