# L7 / Task 4 — Короткое замыкание в калькуляторе

Программа получает список операций (прибавить 3, умножить на 2, сменить знак…) и набор чисел. Каждое число проходит
через все операции по очереди, как деталь по конвейеру. Программа показывает, как число менялось на каждом шаге.

Главное: какие операции будут в конвейере, становится известно только **во время работы программы**, из ввода. Поэтому
конвейер — это слайс функций, который программа собирает сама.

## Зачем эта задача

- Почувствовать, что функция в Go — такое же значение, как число: её кладут в слайс, достают и вызывают.
- Понять, зачем замыкание. Функция «прибавить 3» и функция «прибавить 10» отличаются только числом. Вместо двух функций
  пишут одну **фабрику** `makeAdd(n)`, которая возвращает функцию, запомнившую своё `n`.
- Увидеть приём «сначала разобрать, потом выполнять». Операции разбираются из текста один раз, а дальше конвейер просто
  вызывает готовые функции, не зная, что они делают.

Где это в жизни: цепочки обработчиков (middleware) в веб-серверах, фильтры в редакторах фото, этапы обработки данных.
Везде список шагов задаётся настройками, а код, который их выполняет, один.

## Ввод

1. Число `m` — количество операций, 0 ≤ `m` ≤ 10.
2. `m` строк, по одной операции в каждой:

   | Операция | Что делает с числом `x`                                             |
   |----------|---------------------------------------------------------------------|
   | `add N`  | `x + N`                                                             |
   | `mul N`  | `x * N`                                                             |
   | `div N`  | `x / N` — целое деление, как в Go (`-7 / 2` даёт `-3`). `N` не равно 0 |
   | `neg`    | `-x`                                                                |
   | `sq`     | `x * x`                                                             |

   `N` — целое число, может быть отрицательным.
3. Последняя строка — одно или несколько целых чисел через пробел: числа, которые проходят через конвейер.

Ввод всегда корректный: названия операций только из таблицы, числа целые, все промежуточные результаты помещаются
в `int`.

## Вывод

По одной строке на каждое число из последней строки ввода, в том же порядке:

```
<число> -> <после 1-й операции> -> <после 2-й> -> … -> <после последней>
```

Между числами — ` -> ` (пробел, стрелка из двух символов `-` и `>`, пробел). Если операций нет (`m = 0`), строка состоит
только из самого числа.

## Примеры

Ввод:

```
3
add 3
mul 2
neg
1 -5 10
```

Вывод:

```
1 -> 4 -> 8 -> -8
-5 -> -2 -> -4 -> 4
10 -> 13 -> 26 -> -26
```

---

Ввод:

```
4
sq
div 3
add -1
mul 10
-7 4
```

Вывод:

```
-7 -> 49 -> 16 -> 15 -> 150
4 -> 16 -> 5 -> 4 -> 40
```

---

Ввод:

```
0
7 8
```

Вывод:

```
7
8
```

## Как решать

- Напиши функции-фабрики `makeAdd(n int) func(int) int`, `makeMul(n int) func(int) int` и
  `makeDiv(n int) func(int) int`. Каждая возвращает **анонимную функцию**, которая пользуется `n` снаружи себя —
  замыкание.
- Для `neg` и `sq` число не нужно. Хватит обычных функций `func neg(x int) int` и `func sq(x int) int`: их кладут в
  слайс прямо по имени, без скобок.
- Сначала прочитай все операции и собери из них слайс `[]func(int) int`. Только потом обрабатывай числа.
- В цикле по числам не должно быть `switch` или `if` по названиям операций: там только перебор слайса функций и их
  вызов. Названия операций разбираются один раз — при сборке конвейера.

## Подсказки

- Слайс функций собирается как любой слайс: `var steps []func(int) int`, затем `steps = append(steps, makeAdd(3))`.
- Строку вывода удобно копить: `line := strconv.Itoa(x)`, затем `line += " -> " + strconv.Itoa(x)` после каждого шага.
  Для 10 шагов `+=` — нормально. Для тысяч шагов взяли бы `strings.Builder`.

## Проверь себя

1. Почему `makeAdd(3)` и `makeAdd(10)`, вызванные одна за другой, не мешают друг другу?
   <details><summary>Ответ</summary>

   Каждый вызов `makeAdd` создаёт **свою** переменную `n`, и каждая возвращённая функция держит свою. Это как `counter()`
   с лекции: у каждого вызова свой `count`.
   </details>

2. Чем `makeAdd(3)` отличается от `makeAdd`, а `neg` — от `neg(5)`?
   <details><summary>Ответ</summary>

   `makeAdd` и `neg` без скобок — сами функции, значения типа `func(int) func(int) int` и `func(int) int`.
   `makeAdd(3)` — результат вызова, новая функция типа `func(int) int`. `neg(5)` — результат вызова, число `-5`. В слайс
   конвейера кладут функции типа `func(int) int`: `makeAdd(3)` и `neg`.
   </details>

3. Как добавить новую операцию, например `abs`?
   <details><summary>Ответ</summary>

   Написать функцию `abs` и одну ветку при разборе операций. Цикл, который гоняет числа через конвейер, не меняется
   вообще. Это и есть выигрыш от функций-значений: код «что делать» и код «как выполнять» живут отдельно.
   </details>
