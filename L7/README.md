# L7 — ДЗ к урокам 6 и 7

Это большое ДЗ сразу по двум лекциям: функции, слайсы, строки, map, структуры, методы, интерфейсы и ошибки. В
нём 14 обязательных задач и 5 со звёздочкой ★, то есть необязательных. Задачи разбиты на 6 блоков. Делай их **по
порядку**: внутри блока сложность растёт, а поздние задачи опираются на ранние.

Главное отличие от прошлых ДЗ: задачи не только спрашивают, но и **объясняют**. В каждом `task.md` есть:

- **«Зачем эта задача»** — что ты поймёшь и где это встречается в настоящих программах;
- **«Как решать»** — обязательные требования. Их проверяет преподаватель, читая код;
- **«Проверь себя»** — вопросы для размышления. Ответы спрятаны под спойлером: сначала подумай сам, потом открывай.

Перед каждым блоком ниже есть короткая карточка **«Зачем этот блок»**. Прочитай её до того, как браться за задачи блока:
она объясняет, зачем вообще нужна эта часть языка.

## Зачем этот блок

### Блок 1. Типы, преобразования, байты и руны

- **Зачем столько целых типов?** Тип говорит компилятору, сколько памяти занимает значение и какие числа в него
  помещаются. `uint8` — один байт, от 0 до 255. Чаще всего берут `int`, а маленькие типы нужны там, где формат задан
  извне: файлы, сеть, картинки.
- **Почему Go не смешивает типы сам?** Каждое преобразование — это решение программиста: `f := 3.99`, и `int(f)`
  отбрасывает дробную часть (будет 3), а `var u uint8 = 200`, и `int8(u)` даёт −56. С константами `int(3.99)` и
  `int8(200)` Go вообще не скомпилирует — ещё одна защита. Go заставляет написать это явно, чтобы такое не случилось
  незаметно.
- **Почему `len("Привет")` равно 12?** Строка — это байты в UTF-8, а русская буква занимает 2 байта. Нужны символы —
  работай с рунами.

### Блок 2. Функции как значения и замыкания

- **Зачем класть функцию в переменную?** Чтобы решать, *что делать*, во время работы программы: по настройкам, по вводу
  пользователя. Код, который *выполняет*, при этом не меняется. Так устроены обработчики HTTP-запросов, middleware,
  сортировка «по своему правилу».
- **Зачем замыкание?** Функция запоминает данные, с которыми её создали. Получается маленький объект с одним действием
  без всякой структуры.

### Блок 3. Слайсы, указатели, передача по значению

- **Что значит «всё передаётся по значению»?** Аргумент всегда копируется. Но у слайса копируется только заголовок
  (`ptr`, `len`, `cap`), а массив под ним общий. Отсюда почти все сюрпризы со слайсами.
- **Зачем слайсу `cap`?** Чтобы `append` не переезжал в новый массив при каждом добавлении. Запас ёмкости делает
  добавление в конец быстрым. Но запас — это ещё и общий массив, в который может «писать кто-то ещё».
- **Когда нужна копия?** Когда надо изменить данные, а старая версия ещё нужна, или когда у результата другая форма.
  Транспонированная матрица в task_6 — новая матрица, а не перестановка внутри старой.

### Блок 4. map

- **Зачем map, если есть слайс?** Слайс находит элемент по номеру мгновенно, а по значению — только перебором. map
  находит значение по ключу сразу, сколько бы ни было пар.
- **Почему map не помнит порядок?** Место пары выбирает хеш ключа, а не порядок добавления. Нужен порядок — храни его
  отдельно, в слайсе. В task_7 ты увидишь, что слайс и map часто работают вместе.
- **Что может быть ключом?** Только сравнимый тип: числа, строки, `bool`, указатели, массивы, структуры из сравнимых полей. Хороший
  ключ — половина решения (task_8).

### Блок 5. Структуры, методы, пакеты

- **Зачем структура?** Чтобы данные об одном объекте лежали вместе, а не в трёх параллельных слайсах, которые легко
  рассогласовать.
- **Зачем прятать поля (строчная буква)?** Чтобы данные менялись только через методы, которые соблюдают правила. Баланс
  не может стать отрицательным, если его нельзя менять напрямую (task_9).
- **Когда получатель — указатель?** Когда метод меняет объект. Иначе метод работает с копией, и изменение теряется.

### Блок 6. Интерфейсы, встраивание, nil — самый важный

- **Зачем интерфейс?** Функция говорит «мне нужно что-то, что умеет `Write`» — и работает с терминалом, файлом, строкой,
  сетью и с типами, которые ещё не написаны. Интерфейс — это **рамка**: функция может пользоваться только методами из
  интерфейса и ничем больше.
- **Почему интерфейсы маленькие?** Чем меньше методов требует интерфейс, тем больше типов ему подходит. У `io.Writer`
  один метод — поэтому его реализует половина стандартной библиотеки.
- **Зачем встраивание?** Собрать тип из готовых частей. Встроенная структура приносит поля **и методы**, а вместе с
  ними — подходящие интерфейсы. Наследования в Go нет: встраивание — это композиция.
- **Что такое nil-интерфейс?** Значение интерфейса — пара «тип, значение». Интерфейс равен `nil`, только когда пусты
  **обе** половины. Если положить в него nil-указатель, тип уже есть — и интерфейс уже не `nil`. Это главная ловушка
  интерфейсов (task_14).

## Как читать ввод

Рецепт с урока 5 никуда не делся: сканер создаём **один раз**, потом `in.Scan()` + `in.Text()` на каждую строку.

**Новое: чтение до конца ввода.** Во многих задачах заранее неизвестно, сколько строк придёт. Тогда читай, пока строки
не кончатся. `in.Scan()` возвращает `true`, пока строка прочитана, и `false`, когда ввод закончился. Значит, это обычный
`for` в роли while:

```go
in := bufio.NewScanner(os.Stdin)
for in.Scan() { // false — строки кончились
    line := in.Text()
    // обработать line
}
```

Если первая строка особая (число, режим работы), прочитай её отдельным `in.Scan()` **до** цикла.

Когда вводишь руками в терминале, конец ввода обозначает `Ctrl+D` (macOS, Linux, Git Bash) или `Ctrl+Z`, затем Enter
(PowerShell и cmd).

**Строку на слова** удобно делить через `strings.Fields(line)`: он режет по пробелам и пропускает лишние. Число из
слова — через `strconv.Atoi`. Если в условии сказано «ввод всегда корректный», ошибку `Atoi` можно не проверять.

## Задачи-«интерпретаторы команд»

В задачах 9, 10, 13, 16 и 19 программа получает **команды**, по одной на строку, и выполняет их по очереди. Первое слово
строки — имя команды, дальше её аргументы:

```
push 10
push 20
print
```

Типичный каркас программы в этом случае — чтение до конца ввода и `switch` по первому слову:

```go
for in.Scan() {
    f := strings.Fields(in.Text())
    switch f[0] {
    case "push":
        v, _ := strconv.Atoi(f[1])
        // ...
    case "print":
        // ...
    }
}
```

Что печатает каждая команда, всегда указано в условии. Если про команду сказано «ничего не печатает», значит, она
действительно ничего не печатает.

## Ошибки: как вернуть и как проверить

С задачи 2 функции и методы начинают возвращать ошибки. Всё это было на уроке 6, слайд «Ошибки: error». Короткий
рецепт:

```go
func parseAge(s string) (int, error) { // ошибка — последний результат, тип error
    age, err := strconv.Atoi(s)
    if err != nil {
        return 0, fmt.Errorf("возраст %s: не число", s) // ошибка + нулевое значение результата
    }
    if age < 0 {
        return 0, errors.New("возраст меньше нуля") // текст без подстановок — errors.New
    }
    return age, nil // всё хорошо: ошибки нет — пишем nil
}

age, err := parseAge("abc")
if err != nil {
    fmt.Println("ошибка:", err) // печатает текст ошибки: ошибка: возраст abc: не число
    return
}
fmt.Println(age)
```

- `errors.New("текст")` — ошибка с готовым текстом. `fmt.Errorf("… %s …", x)` — с подстановкой, как `Sprintf`.
- Ошибки нет — пиши `return результат, nil`.
- Функция ошибку **возвращает**, а **печатает** её вызывающий: он знает, что с ней делать.
- `fmt.Println(err)` и `%v` печатают текст ошибки. Ничего специально вызывать не нужно.

Сигнальные ошибки, `%w`, `errors.Is` и `errors.As` нужны только в task_12, и там они объяснены.

## Как читать примеры

Примеры даны блоками «Ввод» и «Вывод». Каждая строка блока — отдельная строка ввода или вывода. Если ввод небольшой, он

## Как проверить себя

Запусти программу и введи строки руками. Или подай весь ввод сразу (macOS, Linux, **Git Bash** на Windows):

```bash
cd L7/task_4
printf '3\nadd 3\nmul 2\nneg\n1 -5 10\n' | go run .
```

Ещё удобнее сохранить пример в файл и подать его на вход:

```bash
go run . < input.txt
```

## Как проверяется

1. Программа запускается на закрытом наборе тестов: он шире примеров. Вывод сравнивается с правильным **символ в
   символ**. Печатай ровно то, что в разделе «Вывод».
2. Время на один тест ограничено (5 секунд). Это важно в task_7: там решение «не тем способом» не уложится во время.
3. Код читает преподаватель. Требования из раздела «Как решать» обязательны: решение в обход не засчитывается, даже если
   тесты прошли.
4. В task_5 и task_14 файл `answers.txt` сверяется автоматически, а `README.md` с объяснениями читает преподаватель.

## Почитать про оценку сложности алгоритмов [нотация big-O] (для задач со ★)

На лекции мы не успели разобрать, как сравнивают алгоритмы по скорости: так называемую O-нотацию, или Big-O. Для задач
17–19 и для общего развития прочитай:

- А. Бхаргава, «Грокаем алгоритмы», глава 1. Лучшее введение для новичков: с картинками и без формул.
- [Big O](https://habr.com/ru/articles/942956/) — короткая простая статья на Хабре: O (1), O (log n), O (n), O (n²) с
  примерами (код на JavaScript, но он читается как Go).
- [Введение в анализ сложности алгоритмов (часть 1)](https://habr.com/ru/articles/196560/) — подробнее: откуда берётся
  O-нотация и почему смотрят на худший случай.
