# L10 / Task 1 — Каталог товаров

## Что мы делаем

Интернет-магазин получает от поставщика список товаров в формате JSON. Данные приходят «грязными»: у товара может не
быть названия, цена может оказаться нулевой, а сам JSON — оборванным. Нужно написать небольшую программу, которая:

1. **разбирает** текст JSON в список товаров на Go;
2. **отсеивает** испорченные товары и запоминает, чем именно каждый плох;
3. **превращает** чистый список обратно в JSON для других систем.

Вся цепочка выглядит так:

```
текст JSON ──ParseProducts──▶ []Product ──FilterValid──▶ чистые []Product ──ToJSON──▶ текст JSON
                                               │
                                               └──▶ список ошибок: что не так с отклонёнными
```

Что будет дальше с этим кодом: `Product` и `Validate` станут каталогом сервера в L11, а те же поля `id`, `name`,
`price`, `in_stock` — входными данными конвертера JSON → CSV в L12.

Ничего не читается из консоли, файлов и сети. Текст JSON записан прямо в `main.go` строкой, а результат ты видишь в
консоли обычными строками. Закрытые тесты вызывают **твои функции** по именам, поэтому имена функций, их параметры и
тексты ошибок, заданные ниже, менять нельзя.

Рассчитывай примерно на 3 часа на базовую часть. Только стандартная библиотека Go.

## С чего начать

1. Создай папку `L10/task_1` и в ней модуль: `go mod init task1`.
2. Скопируй в неё две заготовки из папки задания: `product.go` и `star.go`.
    - В `product.go` уже есть struct `Product` и **четыре функции с пустыми телами** (`// TODO`). Базовое задание —
      добавить теги к struct и написать эти тела.
    - `star.go` нужен только для заданий со ★. Если ★ не делаешь, не трогай этот файл: с ним программа всё равно
      собирается.
3. Создай файл `main.go` с пустой `func main() {}`. В нём ты будешь запускать то, что написал.
4. Делай шаги ниже **по порядку** и после каждого запускай `go run .`.

## Базовое задание

### Шаг 1. Теги в struct `Product`

В заготовке struct уже есть, но без тегов. Тег — это пометка в обратных кавычках после типа поля. Она говорит
`encoding/json`, как это поле называется в JSON. Например:

```go
ID int `json:"id"`
```

Добавь теги всем пяти полям (имена полей менять нельзя):

| Поле      | Тип      | Имя в JSON | Заметка                                                               |
|-----------|----------|------------|-----------------------------------------------------------------------|
| `ID`      | `int`    | `id`       | номер товара                                                          |
| `Name`    | `string` | `name`     | название                                                              |
| `Price`   | `int`    | `price`    | цена в рублях, целое число                                            |
| `InStock` | `bool`   | `in_stock` | есть ли на складе                                                     |
| `Note`    | `string` | `note`     | примечание; если оно пустое, поля в JSON быть не должно (`omitempty`) |

**Проверь.** Временно напиши в `main`:

```go
data, _ := json.Marshal(Product{ID: 1, Name: "Чайник", Price: 2990, InStock: true})
fmt.Println(string(data))
```

Должно напечататься: `{"id":1,"name":"Чайник","price":2990,"in_stock":true}`. Если имена с большой буквы (`"ID":1`) или
есть `"note":""`, значит, с тегами что-то не так.

### Шаг 2. `Validate` — проверка одного товара

```go
func (p Product) Validate() error
```

Метод возвращает ошибку или `nil`, если всё хорошо. Правила проверяются **в таком порядке**, и на первом же нарушенном
метод останавливается. Текст ошибки пиши ровно такой (`errors.New("…")` — новая ошибка с готовым текстом):

| Правило                                                 | Текст ошибки                    |
|---------------------------------------------------------|---------------------------------|
| `ID` должен быть больше нуля                            | `id должен быть больше нуля`    |
| `Name` не пустое (строка из одних пробелов тоже пустая) | `название не может быть пустым` |
| `Price` должен быть больше нуля                         | `цена должна быть больше нуля`  |

`InStock` и `Note` не проверяются. Примеры:

| Товар                                         | `Validate()` вернёт                    |
|-----------------------------------------------|----------------------------------------|
| `Product{ID: 1, Name: "Чайник", Price: 2990}` | `nil`                                  |
| `Product{ID: 0, Name: "Чайник", Price: 2990}` | ошибку `id должен быть больше нуля`    |
| `Product{ID: 1, Name: "  ", Price: 2990}`     | ошибку `название не может быть пустым` |
| `Product{ID: 1, Name: "Чайник", Price: 0}`    | ошибку `цена должна быть больше нуля`  |
| `Product{}` (всё нулевое)                     | ошибку про `id`: она первая            |

### Шаг 3. `FilterValid` — оставить только хорошие товары

```go
func FilterValid(items []Product) (valid []Product, errs []error)
```

Функция проходит по списку и проверяет каждый товар через `Validate`:

- если ошибки нет, товар попадает в `valid`;
- если ошибка есть, в `errs` добавляется ошибка с текстом `позиция <номер>: <причина>`. Номер — место товара в исходном
  списке, **считая с единицы**. Причина — текст ошибки из `Validate`. Пиши так:
  `fmt.Errorf("позиция %d: %w", i+1, err)`. `fmt.Errorf` с `%w` нужен, когда новая ошибка **оборачивает** другую:
  текст склеивается, а исходная ошибка остаётся внутри.

Порядок хороших товаров в `valid` остаётся таким же, как был. Исходный список менять нельзя. Пример:

| Что пришло в `items`                                        | `valid`        | `errs`                                                                             |
|-------------------------------------------------------------|----------------|------------------------------------------------------------------------------------|
| Чайник (ок), Кастрюля (цена 0), Тостер (ок), Ложка (`ID` 0) | Чайник, Тостер | `позиция 2: цена должна быть больше нуля`, `позиция 4: id должен быть больше нуля` |

Если хороших товаров нет совсем, `valid` должен быть **пустым списком, а не `nil`**: `[]Product{}`. Зачем, станет ясно в
шаге 5.

### Шаг 4. `ParseProducts` — разобрать текст JSON

```go
func ParseProducts(data []byte) ([]Product, error)
```

Получает текст JSON (в виде `[]byte`) и возвращает список товаров. Для этого есть `json.Unmarshal`. Что должно
получиться:

| Что пришло                                                     | Результат                                                 |
|----------------------------------------------------------------|-----------------------------------------------------------|
| `[{"id": 1, "name": "Чайник", "price": 2990}]`                 | список из одного товара                                   |
| `[{"id": 1, "name": "Нож", "price": 800, "color": "красный"}]` | список из одного товара: лишнее поле `color` пропускается |
| `[]`                                                           | пустой список (не `nil`) и `nil` вместо ошибки            |
| `[{"id": 1` (JSON оборван)                                     | ошибка                                                    |
| `{"id": 1}` (не массив)                                        | ошибка                                                    |
| `[{"id": 1, "price": "дорого"}]` (строка вместо числа)         | ошибка                                                    |
| `[{"id": 1, "price": 29.9}]` (дробная цена)                    | ошибка                                                    |

Текст любой ошибки должен **начинаться** с `неверный JSON: `, а дальше — исходная ошибка от `Unmarshal`:
`fmt.Errorf("неверный JSON: %w", err)`. Проверять, что цена не равна нулю, здесь не нужно: это работа `Validate`.
`Unmarshal` проверяет **форму** (типы значений), `Validate` — **смысл**; данные извне проверяют на оба вида.

Каркас: `items := []Product{}` (так для `[]` получится пустой список, а не `nil`), затем
`json.Unmarshal(data, &items)` — обрати внимание на `&`. При ошибке верни `nil` и обёрнутую ошибку.

### Шаг 5. `ToJSON` — превратить список обратно в JSON

```go
func ToJSON(items []Product) ([]byte, error)
```

Для этого есть `json.Marshal`. Результат — JSON в одну строку, без пробелов и переносов. Пример для двух товаров:

```
[{"id":1,"name":"Чайник","price":2990,"in_stock":true,"note":"хит"},{"id":2,"name":"Ложка","price":120,"in_stock":false}]
```

У второго товара нет поля `note`: примечание пустое, и `omitempty` его убрал.

Если в функцию передали пустой список **или `nil`**, результат — `[]`. Обрати внимание: `json.Marshal` для `nil`-списка
выдаёт `null`, а другим системам, которые получат выгрузку, нужен список. Поэтому в шаге 3 пустой результат делали не
`nil`, а в этой функции `nil` нужно заменить на пустой список. Каркас: `if items == nil { items = []Product{} }`, затем
`json.Marshal(items)`.

### Шаг 6. `main` — запустить всё вместе

Скопируй в `main.go` этот «ответ поставщика» (потом можешь добавить свои товары):

```go
const raw = `[
  {"id": 1, "name": "Чайник", "price": 2990, "in_stock": true, "note": "хит"},
  {"id": 2, "name": "Кастрюля", "price": 0, "in_stock": true},
  {"id": 3, "name": "   ", "price": 120, "in_stock": false},
  {"id": 0, "name": "Ложка", "price": 120, "in_stock": true},
  {"id": 5, "name": "Тостер", "price": 4500, "in_stock": false},
  {"id": 6, "name": "Нож", "price": 800, "in_stock": true, "color": "красный"}
]`
```

В `main` сделай по порядку:

1. Разбери `raw` через `ParseProducts`. Если вернулась ошибка, выведи её и закончи.
2. Отфильтруй список через `FilterValid`.
3. Выведи, сколько товаров принято и сколько отклонено, и причину для каждого отклонённого.
4. Преврати принятые товары в JSON через `ToJSON` и выведи результат.
5. Покажи, что бывает с оборванным JSON: передай в `ParseProducts` строку `[{"id": 1` и выведи ошибку.

Формат вывода свободный, его проверяет преподаватель глазами. Для `raw` выше у тебя должно получиться примерно так
(принято три товара, отклонено три):

```
принято: 3, отклонено: 3
  отклонено: позиция 2: цена должна быть больше нуля
  отклонено: позиция 3: название не может быть пустым
  отклонено: позиция 4: id должен быть больше нуля
выгрузка: [{"id":1,"name":"Чайник","price":2990,"in_stock":true,"note":"хит"},{"id":5,"name":"Тостер","price":4500,"in_stock":false},{"id":6,"name":"Нож","price":800,"in_stock":true}]
битый JSON: неверный JSON: unexpected end of JSON input
```

Если принялись и отклонились те же товары, а тексты ошибок совпадают, базовая часть готова.

## ★ Задание со звёздочкой, часть 1: товар из значения неизвестного типа

Иногда данные приходят в самом общем виде: как значение типа `any`. Например, если разобрать JSON без struct, получится
`map[string]any`. Функция в файле `star.go` должна понять, что внутри, и собрать товар:

```go
func FromAny(raw any) (Product, error)
```

Примеры:

| Что передали                                                                                                 | Что вернёт функция                                               |
|--------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------|
| `Product{ID: 1, Name: "Чайник", Price: 2990}`                                                                | этот же товар и `nil`                                            |
| `&Product{…}` (pointer на товар)                                                                             | товар, на который он указывает; для `nil`-pointer — любая ошибка |
| `map[string]any{"id": 3.0, "name": "Тостер", "price": 4500.0, "in_stock": true}`                             | `Product{ID: 3, Name: "Тостер", Price: 4500, InStock: true}`     |
| любое другое значение: строка, число (`42`, `3.14`), `true`, `nil`, slice, `map` другого типа, другой struct | пустой `Product{}` и ошибка с текстом `некорректный тип данных`  |

Откуда берётся `map[string]any` и почему числа в нём дробные (`3.0`)? Попробуй:

```go
var v any
json.Unmarshal([]byte(`{"id": 3, "name": "Тостер", "price": 4500, "in_stock": true}`), &v)
fmt.Printf("%T\n", v) // map[string]interface {}
fmt.Printf("%T\n", v.(map[string]any)["id"]) // float64
```

Когда JSON разбирают без struct, `encoding/json` кладёт **любое** число в `float64`. Поэтому для `map` нужны такие
правила:

- ключи `id`, `name`, `price`, `in_stock` обязательны. Ключ `note` — по желанию;
- `id` и `price` приходят как `float64`; их нужно превратить в `int` и убедиться, что число целое (`1.5` — ошибка);
- `name` и `note` — строки, `in_stock` — `true` или `false`. Ключа нет или тип не тот: вернуть `Product{}` и ошибку
  (текст свободный, назови в нём поле);

**В конце любой собранный товар проверь через `Validate`** — пришёл он struct, pointer или `map`. Функция обещает вернуть
годный товар, а цена `0` одинаково плоха, откуда бы она ни пришла. Если `Validate` вернула ошибку, верни `Product{}` и
эту ошибку.

**Программа не должна вызывать panic ни на каком входе.** Проверяй тип безопасно: `f, ok := x.(float64)` или
`switch x := raw.(type)`.

Каркас:

```go
var p Product
switch v := raw.(type) {
case Product:
    // p = v
case *Product:
    // проверь v на nil, потом p = *v
case map[string]any:
    // собрать p из map (ключи и типы — по правилам выше)
default:
    // вернуть Product{} и ошибку «некорректный тип данных»
}
// проверить p через Validate
```

В `main` вызови `FromAny` для товара, для `map`, полученной из JSON-строки, и для обычной строки, и выведи результаты.

## ★ Задание со звёздочкой, часть 2: шапка таблицы по тегам

Скоро товары понадобится выгружать в таблицу, а у таблицы есть шапка — названия колонок. Хранить их удобно прямо в
struct, вторым тегом.

1. Добавь каждому полю `Product` второй тег `label` с названием колонки. Теги пишутся через пробел:

   ```go
   ID int `json:"id" label:"Номер"`
   ```

   Названия: `Номер`, `Название`, `Цена`, `В наличии`, `Примечание`.

2. В `star.go` напиши функцию:

   ```go
   func Header(v any) string
   ```

   Она обходит поля struct через package `reflect`, берёт значения тегов `label` и склеивает их через запятую **без
   пробелов**.

| Вызов                                                           | Результат                                                                    |
|-----------------------------------------------------------------|------------------------------------------------------------------------------|
| `Header(Product{})`                                             | `"Номер,Название,Цена,В наличии,Примечание"`                                 |
| `Header(&Product{})`, `Header((*Product)(nil))`                 | то же самое: pointer тоже подходит, даже `nil` — тип известен и без значения |
| `Header(Order{})`, где `Order` — другой struct с тегами `label` | её названия колонок                                                          |
| `Header(42)`, `Header("текст")`, `Header(nil)`                  | пустая строка `""`, и никакой panic                                          |

Функция должна работать **с любым struct**, не только с `Product`. Поле без тега `label` пропускается. В `main` выведи
`Header(Product{})`.

## Подсказки

- **Тег не работает, а ошибки нет?** Компилятор формат тегов не проверяет. Пары пишутся через пробел, значения — в
  двойных кавычках: `` `json:"in_stock" label:"В наличии"` ``. Всегда проверяй результат через `json.Marshal`.
- **Поля с маленькой буквы `encoding/json` не видит.** Поэтому `ID`, а не `id`.
- **В `Unmarshal` передавай адрес:** `json.Unmarshal(data, &items)`. Иначе получишь ошибку.
- **Как получить из `Unmarshal` пустой список, а не `nil`:** начни с `items := []Product{}` и разбирай в `&items`.
- **Строка из одних пробелов:** `strings.TrimSpace(p.Name) == ""`.
- **Целое ли число во `float64`:** `f == float64(int(f))`.
- **`reflect` и pointer:** бери **тип** через `t := reflect.TypeOf(v)`, а не значение через `reflect.ValueOf(v).Elem()`:
  у `nil`-pointer значения нет, а тип есть. Если `t.Kind() == reflect.Pointer`, то `t = t.Elem()` даёт тип, на который
  смотрит pointer. Для `nil` без типа `reflect.TypeOf` возвращает `nil`: обработай этот случай до любого вызова метода.
  Число полей — `t.NumField()`, поле — `t.Field(i)`, тег — `t.Field(i).Tag.Get("label")`.
- **Склеить строки через запятую:** `strings.Join(части, ",")`.
- **Не вызывай `log.Fatal` и `os.Exit` внутри функций каталога:** они должны возвращать ошибку, а не завершать
  программу.

Дерево репозитория, то, что проверяют тесты, и способ сдачи смотри в [README](../../README.md).

## Зачем эта задача

- **Теги `json:"…"` связывают имя поля в Go с именем в JSON.** `omitempty` убирает пустые поля из выгрузки.
- **`Marshal` и `Unmarshal` — две стороны одной работы.** Данные пришли извне, поэтому ошибку `Unmarshal` нельзя
  пропускать.
- **Разобрать JSON — ещё не значит проверить его.** `Unmarshal` скажет, что цена не число, но не заметит, что она равна
  нулю.
- **`[]` и `null` — разные вещи.** `nil`-список превращается в `null`, пустой — в `[]`.

## Проверь себя

1. Зачем нужна `Validate`, если `Unmarshal` уже вернул `nil`, то есть JSON «разобрался»?
   <details><summary>Ответ</summary>

   `Unmarshal` проверяет **форму**: что в полях лежат значения нужных типов. Смысла он не знает: цена `0` — корректное
   число, а товар с такой ценой нам не нужен. Форму проверяет разбор, смысл — наша функция.
   </details>

2. (★) Почему число из `map[string]any` приходится проверять как `float64`, а не как `int`?
   <details><summary>Ответ</summary>

   JSON не различает целые и дробные числа: это просто «число». Когда тип заранее неизвестен, `encoding/json` кладёт
   любое число в `float64`, чтобы поместились и `42`, и `29.9`. Проверка `m["id"].(int)` никогда не сработает: `ok`
   будет `false`. Поэтому сначала берём `float64`, а потом смотрим, что дробной части нет.
   </details>

3. (★) Чем `Header` отличается от обычной строки `"Номер,Название,…"`, записанной в коде?
   <details><summary>Ответ</summary>

   Записанная строка живёт отдельно от struct: добавили в `Product` поле, шапку забыли поправить, и колонки разъехались.
   `Header` читает названия из самой struct, поэтому шапка всегда совпадает с полями. Так же `encoding/json` узнаёт
   имена полей из тегов: он не знает ваших struct заранее и читает их через `reflect`.
   </details>
