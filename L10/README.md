# L10 — ДЗ к уроку 10: каталог товаров, JSON и reflect

Одно задание, но уже похожее на настоящее приложение: модуль каталога магазина. Он описывает товар, проверяет «грязные»
данные от поставщика и готовит JSON-выгрузку. Рассчитывай примерно на 3 часа на базовую часть. Всё работает в памяти:
файлов и сети пока нет, данные записаны прямо в `main.go`.

| Задание                                          | Что тренируем                                                                       |
|--------------------------------------------------|-------------------------------------------------------------------------------------|
| [task_1 — Каталог товаров](tasks/task_1/task.md) | struct с тегами, `json.Marshal` и `json.Unmarshal`, ошибки разбора, проверка данных |
| ★ там же — товар из значения неизвестного типа  | `any`, утверждение типа `x.(T)`, `map[string]any` и `float64` из JSON               |
| ★ там же — шапка таблицы по тегам               | `reflect`: обход полей любого struct и чтение тегов                                 |

В `task.md` есть «Подсказки», «Зачем эта задача» и «Проверь себя» с ответами под спойлером.

### Сквозное приложение

| ДЗ  | Что строим                                                           | Что берём из прошлого ДЗ                                                            |
|-----|----------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| L10 | модуль каталога в памяти: `Product`, `Validate`, JSON туда и обратно | —                                                                                   |
| L11 | сервис каталога на `net/http`, модуль `shop`                         | `Product` и `Validate` из L10 (без `Note` и без проверки `id`)                      |

## Что можно использовать

Всё, что было на уроках 5–10, и только стандартную библиотеку.

## Что в папке задания

Две заготовки: [`product.go`](tasks/task_1/product.go) и [`star.go`](tasks/task_1/star.go). В них уже написаны имена и
сигнатуры функций, которые вызывает проверка. Сигнатуры менять нельзя. Если ★ не делаешь, `star.go` оставь как есть: в
нём функции-заглушки, и программа всё равно соберётся.

## Как проверять себя

После каждого шага запускай `go run .` и сравнивай вывод с примерами в `task.md`.

## Как проверяется

1. Закрытые тесты вызывают `Validate`, `FilterValid`, `ParseProducts`, `ToJSON` (и для ★ — `FromAny`, `Header`). Они
   проверяют: теги (как выглядит JSON товара, пропадает ли пустое `note`), тексты ошибок символ в символ и номера
   позиций, сохранность порядка и исходного списка, что везде вместо `null` получается `[]`, и что функции не вызывают
   panic на странных входах.
2. Оценка ставится по базовой части; ★ отмечается отдельно.
3. Код читает преподаватель: теги стоят на полях, в `main.go` есть и корректные, и испорченные записи, `Header`
   построена через `reflect`, а не склеена вручную.
