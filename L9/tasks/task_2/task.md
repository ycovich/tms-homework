# L9 / Task 2 — Склад без лишних продаж

На складе лежит товар. Покупатели нажимают «Купить» одновременно, каждое нажатие — отдельная горутина. Нельзя продать
больше, чем есть: если остался один чайник, а купить его хотят трое, продаём одному, двум отказываем.

## Зачем эта задача

- **Мьютекс защищает общие данные.** Остатки на складе — одна `map` на все горутины. Без мьютекса горутины одновременно
  меняют `map`, и программа падает с ошибкой `concurrent map writes` или считает неверно.
- **Проверка и изменение — под одним замком.** «Есть ли товар?» и «списать товар» должны идти вместе. Если между ними
  отпустить мьютекс, две горутины успеют увидеть «остался один» и продадут его дважды. Это гонка в логике из лекции.
- **`atomic` для простого счётчика.** Сколько всего было покупок, удобно считать через `atomic.Int64`: без мьютекса.
  Ответ здесь известен заранее (это число строк с покупками), но считай именно в горутинах: тренируем `atomic`.

## Ввод

Сначала остатки — строки `<товар> <количество>`, затем строка `---`, затем покупки: по одной строке `<товар>` на
каждое нажатие «Купить». **Покупка** — одно нажатие, удачное («продано») или нет («отказ»). Каждая покупка — одна штука. Все товары из покупок есть в остатках. Остаток — от 0 до 30,
покупок — до 300.

## Вывод

Для каждого товара из остатков, **по алфавиту**:

```
<товар>: продано <x>, отказов <y>, осталось <z>
```

Последней строкой — `всего покупок: <n>`: все нажатия вместе с отказами.

## Пример

Ввод:

```
чайник 3
тостер 1
---
чайник
тостер
чайник
тостер
чайник
чайник
```

Вывод:

```
тостер: продано 1, отказов 1, осталось 0
чайник: продано 3, отказов 1, осталось 0
всего покупок: 6
```

Чайников было 3, купить хотели 4 раза: трое купили, одному отказали.

## Как решать

1. Сделай структуру склада, как на лекции, — мьютекс внутри:

   ```go
   type Stock struct {
       mu      sync.Mutex
       left    map[string]int // сколько осталось
       sold    map[string]int // сколько продали
       refused map[string]int // сколько раз отказали
   }
   ```

2. Метод `func (s *Stock) Buy(item string)`:
   - `s.mu.Lock()` и `defer s.mu.Unlock()`;
   - если `s.left[item] == 0` — увеличь `refused` и выйди;
   - иначе `time.Sleep(time.Millisecond)` — **оформление покупки, оно обязательно**, — потом уменьши `left` и
     увеличь `sold`.
3. Прочитай остатки до строки `---`, потом все покупки в слайс.
4. Каждую покупку запусти в своей горутине: `s.Buy(item)` и `total.Add(1)`, где `var total atomic.Int64`.
   Дождись всех через `WaitGroup`.
5. Отсортируй названия товаров (`slices.Sort`) и напечатай итог.

`time.Sleep` между проверкой и списанием — не ошибка, а часть условия: в настоящем магазине оформление тоже занимает
время. Именно из-за него неправильное решение продаёт лишнее, и тесты это ловят.

## Подсказки

- **`map` в структуре надо создать:** `&Stock{left: map[string]int{}, sold: map[string]int{}, refused: map[string]int{}}`.
  В `nil`-map писать нельзя — будет panic.
- **Порядок покупок случайный**, но итог от него не зависит: каждая покупка — одна штука, поэтому продано
  `min(остаток, сколько хотели)`.
- **`total.Load()`** — прочитать значение `atomic.Int64` в конце.

## Проверь себя

1. Студент написал `Buy` так. Тесты показывают «осталось -1» и меньше. Почему?

   ```go
   func (s *Stock) Buy(item string) {
       s.mu.Lock()
       ok := s.left[item] > 0
       s.mu.Unlock()
       if !ok {
           // ... отказ
           return
       }
       time.Sleep(time.Millisecond)
       s.mu.Lock()
       s.left[item]--
       s.sold[item]++
       s.mu.Unlock()
   }
   ```

   <details><summary>Ответ</summary>

   Между проверкой и списанием мьютекс отпущен. Пока одна горутина «оформляет покупку», три других тоже видят
   «остался один» и тоже идут списывать. Каждое отдельное действие защищено, а вся операция — нет. Проверку и
   изменение держат под **одним** `Lock`.
   </details>

2. Покупки всё равно идут по одной — ведь `Buy` держит мьютекс. Зачем тогда горутины?
   <details><summary>Ответ</summary>

   Здесь — незачем, задача учебная. В настоящем сервере под мьютексом держат только короткую работу с общими данными,
   а всё остальное (оплата, письмо покупателю) идёт параллельно. Чем меньше кода под замком, тем больше
   выигрыш от горутин.
   </details>
