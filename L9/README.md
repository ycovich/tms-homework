# L9 — ДЗ к уроку 9: WaitGroup, Mutex, atomic, пул воркеров, context

Четыре небольшие задачи, по одной на каждый инструмент с лекции. Рассчитывай примерно на 3–4 часа. Все задачи — про
интернет-магазин: страница товара, склад, рассылка писем.

Делай задачи **по порядку**: task_4 продолжает task_1, а сложность растёт от задачи к задаче.

| Задание                                                  | Что тренируем                                                                |
|----------------------------------------------------------|------------------------------------------------------------------------------|
| [task_1 — Страница товара](tasks/task_1/task.md)         | `sync.WaitGroup`: дождаться группы горутин; результат — в свою ячейку слайса |
| [task_2 — Склад без лишних продаж](tasks/task_2/task.md) | `sync.Mutex`: проверка и списание под одним замком; `atomic`-счётчик         |
| [task_3 — Рассылка писем пулом](tasks/task_3/task.md)    | пул воркеров: ровно K горутин берут работу из одного канала                  |
| [task_4 — Не ждать дольше лимита](tasks/task_4/task.md)  | `context.WithTimeout` и `select`: бросаем ответы, которые опоздали           |

В каждом `task.md` есть «Зачем эта задача», «Как решать» и «Проверь себя» с ответами под спойлером. Читай «Проверь себя»
после решения: там разобраны ошибки, которые делают чаще всего.

## Что можно использовать

Всё, что было на уроках 5–9: горутины, каналы, `select`, таймеры, `sync.WaitGroup`, `sync.Mutex`, `sync/atomic`,
`context`.

Нельзя:

- `time.Sleep`, чтобы **дождаться** горутин. `Sleep` можно только там, где он **изображает работу** и об этом сказано в
  условии;
- в task_1 — каналы: эта задача про `WaitGroup`;
- внешние библиотеки.

## Как читать ввод

Как в L8: сканер создаём один раз и читаем до конца ввода.

```go
in := bufio.NewScanner(os.Stdin)
for in.Scan() { // false — строки кончились
    f := strings.Fields(in.Text())
    // ...
}
```

Если первая строка особая (в task_3 и task_4), прочитай её отдельным `in.Scan()` **до** цикла.

Проверять удобно так: положи пример из условия в файл `in.txt` и запусти `go run . < in.txt`. На Windows — в Git Bash; в
PowerShell русские буквы при передаче через `|` могут сломаться.

## Проверка на гонки: `-race`

Перед сдачей запусти каждую задачу с детектором гонок:

```bash
go run -race . < in.txt
```

Если гонок нет, программа работает как обычно. Если есть — Go напечатает `WARNING: DATA RACE`. На Windows `-race`
работает только с установленным компилятором C (gcc). Если флаг не запускается, пропусти шаг:
гонки проверит преподаватель.

## Как проверяется

1. Каждая задача запускается на закрытых тестах, вывод сравнивается с правильным **символ в символ**. Время на один
   тест — 5 секунд. В task_1 и task_3 есть тесты «на время»: решение, которое делает всё по очереди, в них не уложится.
2. Код читает преподаватель. Требования из раздела «Как решать» обязательны: ждём через `WaitGroup`, а не через
   `Sleep`; в task_2 проверка и списание под одним `Lock`; в task_3 ровно K воркеров; в task_4 — `context`.
