# L11 — ДЗ к уроку 11: сервис каталога на net/http

Одно задание, в котором ты пишешь не «решение для проверки», а **набор пакетов, которые потом пригодятся**: логгер,
middleware и запуск сервера. В L12 мы подключим их к новому приложению (DataShifter), поэтому код нужно писать так,
чтобы его можно было взять целиком. Рассчитывай примерно на 4 часа на базовую часть. Только стандартная библиотека Go.

| Задание                                          | Что тренируем                                                                                               |

| [task_1 — Сервис каталога](tasks/task_1/task.md) | маршруты `net/http`, JSON в запросе и ответе, `Mutex`, middleware, `slog`, `Shutdown`, переменные окружения |
| ★ там же — токен и удаление                     | middleware, который останавливает запрос; `DELETE` и код `204`                                              |

## Главное правило: код надо уметь переиспользовать

- **Packages `logging`, `middleware` и `server` ничего не знают о каталоге.** Каталог живёт только в `catalog`.
- **Имена packages, функций и их сигнатуры менять нельзя.** Они уже написаны в заготовках, L12 вызывает их по этим
  именам.
- **Имя package совпадает с именем папки** (`package logging` в папке `logging`).
- **Модуль называется `shop`:** `go mod init shop`. Тогда packages подключаются как `shop/logging`.

Подключать код из другой папки репозитория Go умеет без интернета: в `go.mod` нового приложения пишут `replace`. Как
именно, расскажет ДЗ L12.

## Что можно использовать

Всё, что было на уроках 5–11, и только стандартную библиотеку. Gin и другие фреймворки не нужны.

## Что в папке задания

В [`tasks/task_1`](tasks/task_1) лежат заготовки packages: имена и сигнатуры уже написаны, тела пустые (`// TODO`). Файл
`main.go` ты пишешь сам. Файл `middleware/recorder.go` готов, менять его не нужно. В `middleware/star.go` лежит заглушка
для ★: если ★ не делаешь, оставь её как есть.

## Как проверяется

1. Закрытые тесты вызывают функции packages напрямую: `logging.New`, `middleware.RequestID`, `middleware.Logging`,
   `server.Run` (с настоящим сервером на локальном порту и остановкой посреди запроса), `catalog.NewStore().Handler()`.
   Тексты и коды ответов, заданные в условии, сверяются символ в символ.
2. Тесты packages от `main.go` не зависят, но без него корень модуля не собирается (`go build .`) — в отчёте это будет
   предупреждением. Создай `main.go` сразу, даже пустой.
3. Оценка ставится по базовой части; ★ отмечается отдельно.
4. Код читает преподаватель: общие данные каталога защищены mutex, у сервера заданы timeout, packages `logging`,
   `middleware` и `server` не знают о каталоге, а `main.go` собирает приложение, и оно запускается.
